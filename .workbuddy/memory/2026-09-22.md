## 引擎设计问题审查（未改代码，仅静态阅读）
梳理出以下关键缺陷，作为后续重构的输入：

### 致命级（架构断裂）
1. **Effect 系统从未接线到引擎**：`EffectRegistry` / `SkillRegistry` 只在 `__tests__` 中被实例化，GameEngine / GameBoot 生产代码从未调用 `registerAll` / `loadHeroSkills`。→ 真实对局中 `EventTrigger.handlers` 恒为空，所有卡牌效果与武将技能完全不生效。同理 `damageSystem.registerHook` 从未被调用，6 段伤害流水线是空的。
2. **`rebindState()` 导致 EventDispatcher 的 deps 失效**：deps 在构造函数中 `buildEffectDeps()` 一次性捕获，init 时 `this.state` 与全部子系统被重建，但 deps 未更新、EventDispatcher 也没有 setDeps。→ EffectContext 操作的是被废弃的空 GameState，与 PhaseManager 持有的新 state 不一致。
3. **伤害结算双轨制**：DamageSystem 自建 DamageStage 流水线，与事件系统的 TriggerStage 并行且互不相通。`EffectContext.damageTarget` 先 `executePipeline`（已扣血）再 `dispatch(Damage)` 事件，顺序颠倒，技能无法拦截伤害。

### 严重级
4. EventChain 名不副实的 LIFO：`dispatchAll` 先 pop 再 dispatch（内部又 push）；`processNestedEvents` 只在 Content 阶段后处理，Before/End/After 阶段产生的子事件被延迟。「后发先至」与无懈可击式插入取消均无实现路径（`canceled` 仅在 SkipCheck 检查一次）。
5. 没有「结算点 / 按座次轮询询问」模型，PriorityManager 只按 priority + isLocked 排序，缺少从当前行动玩家起的座次顺序。
6. 直接改状态泛滥，违反 CLAUDE.md 守则第 1 条：`DamageSystem.applyDamage` 直接 `target.hp -=`，`EffectContext.recoverHp / modifyMaxHp / drawCards`、`GameEngine.dealInitialHands`、`PhaseManager.doPhaseDraw/doPhaseDiscard` 均绕过事件与 CardSystem。
7. DamageSystem 钩子全局注册，无持有者归属、无 filter、无优先级、执行顺序即注册顺序。
8. 主公未固定在 0 号位（`assignRoles` 整体 shuffle 身份），而 TurnManager 从 0 号起手 → 先手权规则错误，与 PLAN.md「主公总是玩家0」矛盾。
9. 非确定性随机：`fisherYatesShuffle` / `DefaultRandomService` 用 `Math.random()`，无法 seed → 回放（ReplayEngine）与确定性测试不成立。

### 可维护性级
10. trigger 四 scope（source/player/global/target）语义混乱；`player` scope 依赖 `event.player`，而多数事件创建时未传 player → 该 scope 实际永不触发。CLAUDE.md 只记录了 3 个 scope。
11. 状态机当前状态与 `state.currentPhase` 双写；`registerState(WILDCARD, [GameOver])` 通配注册易与具体转移冲突。
12. `IEffect` 接口膨胀；`frequency`（once/unlimited/oncePerTurn/oncePerRound）无落地执行点；`SkillRegistry.enableEffect/disableEffect`、`EffectContext.modifyEffects` 均为空桩（后者只存了数组长度）。
13. `EventTrigger.getMatchingHandlers` 每个 stage 全量 filter 注册表。
14. 静默失败：`EventDispatcher.createContext` 找不到玩家返回 undefined 直接跳过 handler；多处 `catch {}` 吞异常。
15. 疑似类型错误：`src/core/engine/effect-context.ts:32` 使用 `IGameState` 但未 import（node_modules 未安装，未能跑 type-check 验证）。

## 实测基线（2026-09-22，装好依赖后首次实跑）
- `npm run type-check`：**60+ 错误，exit 2** —— 项目根本编译不过
- `npm run test:unit`：**789 测试，315 失败 / 474 通过；36 文件，20 失败**（README 声称 904 全绿，不实）
- 失败根因分类：
  1. **契约层与实体层不同步（~35 错误）**：`IPlayer` 是纯数据接口零方法，`Player` 类却实现了 `setMark/getMark/isWounded/isDying/getEquipInSlot/hero/markAttackUsed` 等 12 个成员，消费方按 `IPlayer` 取类型 → 全量 TS2339
  2. **`Card.resetCounter()` 不存在**（实体上是 `resetIdGenerator`）→ 20 个测试文件 beforeEach 挂掉 → 315 个失败的绝大部分来源
  3. `CardDefinition` 未从 `@core/entity/card` 导出（只 `import type`）
  4. `IGameState` 缺 `aliveCount`；`IStoreService` 缺 `onChange`
  5. `HeroDefinition` 的 `maxPower`/`skins` 应为可选，`source/heroes/standard.ts` 未填（10 处）
  6. `views/game/index.vue` 用对象字面量断言 `GameController`；`hooks/useSkill.ts` 的 `IHero → Record<string,unknown>` 断言非法
- 结论：绝大多数失败是测试脚手架调错 API，不是逻辑错误；修掉契约层 + 一个方法别名，基线应能接近全绿。但 474 个"通过"的测试验证的是零件，整机（Effect/Skill）仍未接线。

## 重构计划 v2（参考无名杀重写）
- 调研了无名杀（libnoname/noname）架构：**事件名+阶段后缀**（damageBegin/damageEnd…）、**step/goto/finish/cancel 事件对象**、`lib.element.Content` 事件默认处理器、`skill.trigger {player/source/target/global}`、`skill.mod` 修改器、`player.when()`、mark 标记、zhuanhuanji 转换技、equipSkill、group/subSkill、limited/forced/charlotte/firstDo。
- **最关键发现：现有设计只有 trigger，没有 mod。**「所有杀伤害+1」这类全局数值效果无处安放 —— 只能写成 trigger + content 改事件数值，要自己处理优先级/取消/AI 询问。无名杀用 `skill.mod`（纯函数修改器）解决。
- 三种扩展机制分工：**Mod** 管"数值怎么算/能不能做"，**Trigger** 管"流程怎么走/要不要问玩家"，**Content** 管"事件本身做什么"。准则：能用 Mod 一律用 Mod。
- 计划从 v1 的 10 个 Phase 拆到 **27 个**，分 7 组：A 抢救基线(1-2) / B 装配(3-4) / C 事件内核(5-10) / D 技能与扩展(11-17) / E 地基(18-20) / F 规则补全(21-25) / G AI与UI(26-27)。
- 新增 **28 条扩展能力验收清单**作为总验收标准：每个效果必须能在 `source/` 用 ≤15 行实现、零引擎改动。
- 里程碑：M1 可验证(1-2) / M2 活起来(3-4) / M3 结算正确(5-10) / **M4 可扩展(11-17)**★ / M5 规则正确(18-25) / M6 可玩(26-27)。建议最小交付做到 M4。
- 文档：`docs/refactor-plan.md`（v2 全文）、`docs/code-standards.md`（新增 3.4 三种扩展机制分工、3.5 Mod 四条硬约束、3.6 事件命名；守则新增第 9/10/11 条；第 8 节已知偏离改为实测数据并标注负责 Phase）。

### 踩坑记录
- `{...gameStateInstance}` 展开**不会复制原型 getter**（`aliveCount` / `alivePlayers`），所以 `syncGameState` 必须收 `GameStateSnapshot`（来自 `toJSON()`），不能直接传 `GameState` 实例。引擎侧调用点原本就是 `this.state.toJSON()`，正确。
- `ref<GameController>` 在 Vue 类型系统下会因 `UnwrapRef` 剥离类私有字段而报错，必须 `shallowRef`。
- TypeScript 的 `Omit<IGameState,'addLog'>` 在本项目 TS 版本下推断丢失，改为显式声明 `GameStateSnapshot` 接口。
