### 关键设计（别退回老路）

1. **归属用 `owners()` 惰性求值，不是写死持有者字段。** 装备装卸、玩家死亡都会改变持有者；惰性求值让「卸下 → 下次查询自然查不到」成立，零清理代码。
2. **数值与布尔共用一个 `mods` 对象**（`INumericMods & IBooleanMods` 交叉），不要拆两个注册表。一个「藤甲」既要 `damageTo` 又要 `cardEnabled`。
3. **Mod 不可被无懈可击**，所以 Mod 实现里不需要处理取消逻辑。

### 踩过的坑（重要）

1. **测 Mod 别用「血量差」断言。** `applyDamage` 会把实际扣减裁到剩余体力，人一死读到的就是「还能扣多少」而不是「伤害是多少」。改成每次先 `target.hp = 5` 垫高，或直接读结算后的 `values.num`。调试时为此单独开了个 `__scratch.test.ts`，用完即删。
2. **验结算顺序必须用非交换运算。** 一开始用 `×2` 和 `+1`，结果差得不够醒目；换成 `×10` 和 `+1`（11 vs 2）才一眼能看出次序。
3. **`ModQuery` 必须实现 `DistanceMods` 的那三个带 `Of` 后缀的方法名**（`attackRangeOf` 等），否则 `DistanceSystem` 回调调不到。第一版漏了，编译期不报、运行期静默失效。
4. **Edit 并行改同一文件会静默丢一次**（Phase 9 已记录，本轮再次验证）：`target-system.ts` 的 `getMaxTargets` 签名改了两轮才落稳，靠 type-check 才暴露。同文件多次 Edit 务必串行。

### 顺手修掉的真 bug

`TargetSystem.getTargetsForDelayedCard` 里有一行 `c.name === (source as never)`——**拿卡牌名去和玩家对象比**，且算出的 `hasSameDelayed` 从未使用，函数无条件 `return true`。即「判定区已有【乐不思蜀】的人不能再吃一张」这条禁令从来没生效过。改为传入 `card` 并真正按同名过滤。

### 与计划的三处偏差（已写进 refactor-plan Phase 11）

1. 归属用 `owners()` 惰性求值（计划写的是「持有者字段」）。
2. 数值/布尔不拆两个注册表。
3. `ModQuery.distance` / `inRange` 不收 `event`——`DistanceSystem` 回调链没有事件上下文，硬留参数会误导。

### 为什么是「别名」而不是「子接口」

先让 `IEffect extends ISkill`（保留旧字段）。撞墙：新契约的
`selectCard`（需选牌数）与旧契约的 `selectCard`（选择器工厂）**同名不同义**，
接口继承直接冲突（`Types of property 'selectCard' are incompatible`）。
改成别名后问题消失——但前提是**先把所有技能迁完**，旧字段一个都不剩。
所以顺序是：迁完 → 才能降别名。反过来做不通。

### 挖出来的五个真问题（全部是「写了却从未生效」型）

1. **`oncePerTurn` 从未复位。** `CompiledHandler.usedThisTurn` 写了却没人清零 →
   实际等价于 `once`（整局一次）。补了 `resetFrequency` 与三处调用点。
2. **咆哮从未生效。** 在 `turnStart` 写 `player.attackLimit = Infinity`，
   而 `PhaseManager.getPlayableCards` 读的是 `modQuery.cardUsable`。改成 `mod.cardUsable`。
3. **克己从未生效。** 挂在 `phaseDiscardBefore`，而 `executeTurn` 是在**分发阶段事件之前**
   就检查 `shouldSkipPhases` 的。改挂 `phaseUseEnd`；判据从无人写入的
   `usedShaThisTurn` 换成真正被维护的 `player.usedAttackThisTurn`。
4. **连弩 / ±1 马各写了两份 Mod。** `equip-effects`（死）+ `equip-mods`（活）。
   统一分界线：**通用**（按槽位/tag，任何武器、任何藤甲）→ `mods/equip-mods.ts`；
   **属于单张牌**（连弩无限杀、±1 马距离）→ 该牌技能自己的 `mod`。
5. **技能里用 `Math.random()`**（反馈 / 鬼才 / 制衡 / 突袭）违反确定性要求 → 改固定顺序取牌。

## Phase 14 —— SkillRegistry 挂载 / 卸载 / 临时技能 ✅

**结果**：`test` 233/233（新增 19 例）· `type-check` 0 · `oxlint` 0 · `eslint` 0 · `build` 通过

### 核心决断：三套推断合一，删掉两个文件

Phase 14 之前「谁拥有哪个技能」有三套互相矛盾的推断：

| 机制 | 推断方式 | 后果 |
|------|---------|------|
| 触发器 | 只认 `hero.effectIds` | **装备的触发技从没被挂上过**（青釭剑/八卦阵/仁王盾全是死代码） |
| Mod | 现算「英雄写着它 / 装备带着它」 | 数值生效、触发不生效 → 同一张装备半身不遂 |
| 觉醒技 | `enableEffect()` 返回 `true` | 纯装饰；`ctx.modifyEffects` 也只写一个无人读的 mark |

现在归一到 `core/skill/skill-registry.ts` 一张台账；
**删掉** `core/engine/skill-registry.ts` 与 `core/engine/effect-registry.ts`（两份注册表合成一份）。

三种挂载来源：`permanent`（英雄/觉醒/attach，只有显式 detach 能摘）·
`equip`（装备区有这张牌）· `temp`（到期事件摘）。

### 三条「不靠记得调用」的接线（关键经验）

1. **装备装卸的通知挂在 `CardSystem.moveCard`**（进出 `Equip` 区都喊），
   不是挂在 `equipCard` / `unequipCard` 两个入口——**拆装备、顺手牵羊走的是另一条 moveCard 路径**，
   只在入口喊会静默漏掉。
2. **临时技能到期做成一条真的事件钩子**（priority `-1000`，恒最后跑），
   于是 `{event:'damageEnd'}` 无需引擎配合，且天然保证「技能先在本事件上生效，然后才被摘掉」。
3. **新登记的技能通过 `onRegister` 回调补 mod**，否则「开局后才登记」会变成
   触发有效、数值无效的半身不遂。

### 另外两个决断

- **死者不摘钩子**，改在 `skillGate` 里 `!player.alive → false`。
  摘容易，**复活时记得挂回去难**。
- **卸钩子按对象身份撤，不按 skillId 撤**——到期钩子的 id 是合成的，
  按 id 过滤会把它漏成幽灵钩子。

### 顺手修掉的三件事

`ctx.modifyEffects` 空操作 → 真正 attach/detach；
纯 Mod 技能（咆哮）旧代码因「编译不出钩子」而不进台账 → 现在照样记账；
补发 `roundEnd` 事件（否则「持续到轮次结束」这一档永远等不到到期点）。

### 三个真 bug（都是「写得像对的」）

1. **限定技过一轮就复活**：判据是 `usedThisRound`，而它在轮次边界被清零。
   → `limited` / `awaken` 归一到 `frequency: 'once'`，判永不清零的 `usedCount`。
2. **「每回合限一次」实为「每事件限一次」**：运行时状态长在 `CompiledHandler` 上，
   一条技能监听 N 个事件就有 N 份计数。→ 状态上移到台账的挂载记录，handler 持引用。
3. **觉醒技是空桩**（Phase 14 已修 `modifyEffects`，本次补 `ctx.awakenSkill` 语义）。

`usedCount` / `usedThisTurn` / `usedThisRound` / `usedThisPhase` / `awakened` / `convertState`。

频率判定**只有一份实现**，三处共用：EventTrigger 收集时挡、EventCompiler 执行后记账、

`convertible` 的真值在台账，`player.marks` 上是**镜像**、唯一写入点是 `flipConvertState`
