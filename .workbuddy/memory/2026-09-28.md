### 四个「写了也没生效」的坑

1. **虚拟牌只覆盖 `tags` 不覆盖 `id`** → 打出去什么也不发生。
   内容分发按 `card.id` 找 `useCardContent`，「名字像杀、id 还是底牌」查不到内容。
   修法：内容层一律 `viewLike(Sha, {...})`（id/type/tags/effectIds 照抄定义）。
2. **响应窗口看不到虚拟牌** → 龙胆的杀当闪根本打不出去。
   三处候选都只扫 `handCards`：杀的闪响应、濒死求桃、无懈窗口。全补上 `ctx.cardViews()`。
3. **出杀额度被视作绕过**：按底牌 id 记账的话每张红牌自带一次出杀额度。
   `cardUsageKey()` 按 `CardTag.Strike` 记，虚拟杀与真杀共用同一个键。
4. **虚拟牌被当成实体**：翻译放在 `CardSystem` 的三个移动入口
   （`useCard` / `discardCard` / `finishProcessing`），内容层不用知道虚拟牌。

### 两个设计决定

- **虚拟牌 `instanceId` 是推导的**（`virtual:<skillId>:<底牌id...>`），不用自增发号器。
  否则出牌阶段每刷新候选列表同一条视作就换 id，UI 选中项 / 测试编排的应答全对不上号。
- **双面视作由 `ctx.usage` 分流**。龙胆的杀既是可打出的杀、也是被杀时当闪的原料；
  同时摆两面会在出牌阶段冒出「闪」、响应窗口冒出「杀」——两条都错。

### 顺手修的

- `response-inquiry.ts` 里「等 Phase 13 才能执行」的过时注释
- `phase-manager.ts` 尾部的 `setDecisionService` 缩进错乱（在类体内却顶格）
- `cancel-chain.ts` 无懈窗口纳入虚拟牌

## Phase 17 —— `group` / `subSkill` / 全局钩子 / `when()` ✅

**结果**：`test` 296/296（新增 28 例）· `type-check` 0 · `oxlint` 0 · `eslint` 0 · `build` 通过

### 新增

- `src/core/event/global-hook.ts` —— `GlobalHookRegistry`（`on/off(id)/clear/count`）
- `src/core/event/when.ts` —— `WhenBuilder`（`filter/scope/priority/once/then/finish`）+ `whenOf()`
- `src/__tests__/skill/skill-composition.test.ts`（15 例）
- `src/__tests__/event/global-hook.test.ts`（13 例）
- 契约：`CompiledHandler.ownerless`、`IWhenBuilder` / `IWhenHandle`、`ISkillContext.when()`
- `EffectContextDeps.eventTrigger`（`ctx.when()` 要把监听挂上去）

### 三个「写了也没生效」的坑

1. **无持有者的钩子没有 `ctx.player`**：`createContext` 按 `handler.playerId` 找人，
   找不到就整条跳过。全局钩子没有持有者，playerId 写谁都变成「只有那人出牌才触发」。
   → `CompiledHandler.ownerless`：上下文玩家取自事件本身（`event.player ?? event.source`），
   并跳过技能放行闸。
2. **`expandSubSkills` 只返回子技能** → 有子技能的父技能自己的 mod / trigger 从未登记
   （父技能被它的子技能吃掉）。现在返回 `[父, ...子]`；旧断言已更新。
3. **子技能 Mod 登记两遍**：台账摊平后逐条 `onRegister`，`registerSkillMods` 又展开一次。
   → 展开只留台账一处，Mod 装配不再展开。

### 两个设计决定

- **`group` 是派生挂载**（台账记 `groupOwner`）：主技能被摘时全组跟着走；
  装备区对齐**不单独摘**组内那份，否则「英雄自带主技能 + 穿着同名牌」时组内技能会消失。
  递归展开要带 `visited`，互为组员是合法写法，没有它栈溢出。
- **`SkillRegistry.clear()` 不再调 `eventTrigger.clear()`**：后者会把全局钩子与
  `when()` 监听一起抹掉（它们挂在同一个触发器上）。改成逐条 `detachEntry`。

### 环境备注

本轮 Bash shim 可用（`grep` / `node -e` 正常）。oxlint 的 `unicorn(no-thenable)`
豁免注释要写成 `// oxlint-disable-next-line no-thenable`（带插件名的写法不生效）。

## Phase 18 —— 确定性随机与回放 ✅

**结果**：`test` 313/313（新增 17 例）· `type-check` 0 · `oxlint` 0 · `eslint` 0 · `build` 通过

### 新增

- `src/core/services/seeded-random.ts` —— `SeededRandomService`（mulberry32，
  `snapshot()` / `restore()` / `calls`）、`hashSeed`（FNV-1a）、`randomSeed()`
- `src/core/utils/clock.ts` —— `LogicalClock` + 单例 `gameClock`
- `src/core/replay/` —— `replay-engine.ts`（录/放/比）、`decision-recorder.ts`
  （录制 + `ReplayDecisionService` 指纹校验 + `ReplayDivergenceError`）、
  `event-trail.ts`（挂 Phase 17 全局钩子记事件流水）、`auto-decision.ts`（定式自动玩家）
- `src/__tests__/engine/determinism.test.ts`（17 例）
- 契约：`IGameState.nextLogId()`；`Card.resetIdGenerator()`

### 四个「看着对、其实不对」的坑

1. **卡牌实例号跨局自增** —— `Card._idGenerator` 是模块级单例，第二局接着上一局编号。
   同种子也复现不出同一局（局面一样，`instanceId` 全不一样）。
   → `GameEngine.init()` 里 `Card.resetIdGenerator()` + `gameClock.reset()`。
2. **AI 与牌堆共用一条随机流** —— AI 的思考延迟 / 差不多好时随机挑一张都吃随机数；
   回放时没有 AI，消耗次数不同 → 洗牌序列整体错位。→ AI 独立一条流（按种子派生）。
3. **「回放跑完了」是假信号** —— 篡改**应答**（而非请求）不触发指纹校验：
   引擎照样一圈圈问下去，只是每步答案不同，最后照样「跑完」，放出来的却是另一局。
   → 录像没走完即抛 `ReplayDivergenceError`。
4. **为「显式排序」而排序会抹掉语义** —— 给 `SkillRegistry.getSkills` 加字母排序后
   `main` 掉到 `a`/`b` 之后，Phase 17 两条断言挂了（这就是本轮唯一 2 个红灯）。
   台账是 `Map`，插入序本就是规格承诺的确定性顺序。已撤销排序并在
   code-standards §3.12 补上判据：**顺序有语义时不要排**。

### 两个设计决定

- **回放只比「输入→输出」，不做状态快照对比**。逐帧快照会把引擎内部实现钉死在
  录像里（改个字段名就全废）。比事件流水 → 日志指纹 → 终局摘要 → 结果四项；
  `logFingerprint` 剔除 id 与 timestamp，`result` 比 winner/reason/totalRounds 不比 `endedAt`。
- **`Date.now()` 不进状态，只留在呈现层**。事件时间戳与结算 `endedAt` 走 `gameClock`；
  AI 的 `decisionLogs`、boot 日志、`randomSeed()` 兜底仍用挂钟——它们不参与任何比对。

### 性能经验

8 人 3 轮 AI 对局单跑 356s：`AIController` 每问一次扫一遍手牌约 24s/轮。
→ 多数回归用例改用 `AutoDecisionService`（不思考、秒回），`maxRounds` 压到 2，
只保留 1 条真 AI 用例。同样覆盖度下 17 例 18.4s。
