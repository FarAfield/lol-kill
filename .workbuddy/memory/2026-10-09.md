## T5 · D34 人类决策通道 + D35（结清）

新增 `src/services/human-decision.ts`。**它唯一的正事是按座位分流**：

- 不能把 UI 直接当决策服务 —— 引擎对**所有座位**提问，
  那等于让人替 AI 打牌。`isHuman(player)` 判 `seatIndex === humanSeatIndex`，
  判的是**座位**不是「是不是当前行动者」（【杀】打过来时被问的人往往不是回合归属者）。
- **铁律：每个方法都必须有答案。** 这些问题是在事件流水线被 pause 挂起时问出来的，
  一个永不 resolve 的 Promise 就是一次**事件栈死锁**。所以 UI 通道全可选，
  没登记就回落缺省（拒绝 / 不出 / 自动弃前 N 张）——宁可替他做决定，也不能让整局卡住。
- 三个查询口 `setCardBudget` / `setModQuery` / `setSkillRegistry` **必须转发给兜底**，
  不转就是蒙上 AI 的眼睛。
- 视图收口成一个 `createSession()`：开局与「再来一局」共用。以前这两处各写一遍构造，
  第二遍漏了 `setDecisionService`，于是**第二局又变回不会防守的单机**。

`useResponse` 同时从「单向命令」改成「能带回答案的询问」：`open(): Promise<string | null>`
（原来返回 `void`，`confirm()` 里那句 `ctrl.respondToWindow(...)` 实测只做了一句
`syncToStore()`，**什么也没真答复**）。`controllerGetter` 形参随之删除 —— 留着就是一句谎话。
`discardStalePromise()`：顶掉旧问题时必须把旧的那个答复掉（按「不出」），
悬着的 resolve **不报错、不红测试**，只是那条 await 永远不返回。

## 引擎侧（T1）

- `start()` 只开局：GameStart → `beginRound()`（顺带把先手设成主公）→ 完。
  **不再调 `executeTurn()`** —— 那一句正是「界面看起来完全死了」的一半成因。
- `startGame()` **不 await 到整局结束**（`runGameLoop` 是个 while）。
  开局与「等结果」分开：`startGame()` 只把循环跑起来，
  整局结果走**新加的 `whenFinished(): Promise<IGameResult>`**。
  `loopPromise` 上挂一个 `.catch(() => { isRunning = false })`，
  否则引擎内部一次异常就变成没人管的 unhandled rejection。
- **`onPhaseSync`**：`PhaseManager` 新增回调，进阶段 / 出阶段 / 打完一张牌各喊一次，
  由引擎接到 `syncState()`。`PhaseManager` 不认识 Store，同步只能引擎做。
  没有它，界面上「轮到谁 / 现在什么阶段」会停在上一回合 ——
  形态丁下阶段是一路跑过去的，UI 只能靠同步看见。

## UI 侧（T2）

### 一个容易漏的坑：computed 没有响应式依赖

视图里 `availableActions = computed(() => ctrl.getAvailableActions())`
只依赖 `session`（shallowRef），**引擎挂起提问时它不会重算** ——
控制器里的 `pending*` 是普通字段，Vue 看不见。
修法是在这个 computed 里 `void uiState.value`，让它挂上 Store 的依赖：
引擎每同步一次（`syncFromEngine` 换一个新对象）它就重算一遍。
**凡是「控制器里的可变状态进了 computed」，都要先问一句它到底依赖谁。**

## 死锁纪律（T3）

`settleAllPending()`（出牌 → `null`、弃牌 → 前 N 张）在 `cleanup()` 里调，
于是 `destroy()` / 卸载 / 「再来一局」/ 重置会话全都覆盖。
视图收口成一个 `resetSession()`（响应弹窗那个在这里 `response.close()`，
控制器那两个在 `destroy()` 里）—— **所有出口走同一个函数**，D34 的教训。
断言：挂起时 `destroy()` → 那条 Promise 必须拿到 `null`。
**变异：撤掉 `cleanup()` 里的 `settleAllPending()` → 正好红这一条。**

## 测试踩的两个坑

1. **`maxRounds` 是 100。** 循环现在在后台跑，测试要是等整局结束得先给这一局设上限
   （`{ ...standard5pConfig, maxRounds: 2 }`）。`skill-panel.test.ts` 和
   `game-board.test.ts` 都是这么改的。
2. **别断言「第二轮又轮到人」。** 实测人会在第一轮被乐不思蜀命中，
   第二轮的**出牌阶段被跳过** → 永远等不到第二次出牌提问。
   改成断言「其余四个座位依次被问 + `currentRound >= 2`」，稳。
   （教训：断言「它会再来一次」之前，先想清楚有没有规则能让它不来。）

## 换皮的两条边界（下次改这里先看）

- **换皮管不到引擎已经拼好的整句**：`effect-context.ts:350` 之类的日志
  直接写 `${hero.name} 回复了 N 点体力`。单字牌名（杀 / 闪 / 桃 / 酒）
  做子串替换必然误伤（「击杀」里的「杀」）→ 登记 **D40**，
  正解是引擎日志只记事件与 ID，文案由展示层拼（那是一次重构，不是换皮）。
- **`player.attackRange` 不查 ModRegistry**（`Player` 是纯实体），
  所以 Mod 带来的数值变化在界面上根本看不见 → 登记 **D41**。

## 又一个「等于某值也绿」的变体

换皮的断言最容易写成「显示的名字 === 查表结果」——那是句废话。
有效的是**同一时刻两边都取一次值**：Store 派生出「德莱厄斯」，
而引擎真值仍是「关羽」。少取一边，换皮倒流进引擎也发现不了。
