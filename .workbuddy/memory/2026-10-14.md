### D44 —— 改判改错了对象（真 bug，被英雄池掩盖了三年）

一次判定里有两张牌：延时锦囊自己 + 翻出来的结果牌。判定有**两条发起路径**，
往事件里放的键**同名不同义**：

- 判定阶段 `PhaseManager.doPhaseJudge`：`judgeCard` = 延时牌，`judgeResultCard` = 结果牌
- 内容层 `EffectContext.judge`：`judgeCard` = **结果牌**（没有 judgeResultCard）

【鬼才】读 `judgeCard` 取「判定牌」→ 在真实判定流程里换掉的是**延时锦囊**，
改判从未生效过，还顺手把乐不思蜀摸进了司马懿手里。一直没被发现，是因为
标准 5 人局原先**分不到司马懿**（10 名英雄 × `heroSelectCount: 3`，
`startIdx = (i * 3) % 10`）；凑成 11 名后 `% 11`，4 号位变成司马懿。

修法（照「一件事只许有一个答案」）：
1. 只留一个键 `judgeResultCard`，常量与读写函数收在 `src/core/event/judge-keys.ts`
   （`JUDGE_RESULT_CARD_KEY` / `judgeResultCardOf` / `setJudgeResultCard`）。
2. 收尾逻辑：判定阶段有一份三分支、内容层只有一行不完整的 → 合成
   `CardSystem.finishJudgeResult()` 一个出口，两条路径都调它。

**测试纪律**：【鬼才】是**全局**触发，局里只要有司马懿，每一次判定都换成
他的手牌。凡断言「翻出来的花色 → 延时锦囊生效与否」的用例，英雄池必须钉死
（脚手架新增 `NO_GUICAI_HEROES` + `createTestEnv(decisions, overrides)`）。
这次一口气红了 4 条，全是这一个原因。

## D45 —— 图文版卡死在第一回合（用户实测发现，已结清）

用户原话：**「文字版可以正常运行，图文版直接卡在第一回合了」**。
文字版全员 AI、没有「人要回答」这一环所以能跑；图文版多出来的正好就是这一环。

### 根因：引擎挂起提问时不推状态

形态丁下引擎是唯一推进者，`doPhaseUse` 里 `await askForCardPlay(...)` 挂起等人。
但 `PhaseManager.executeTurn` 对每个阶段是**先** `currentPhase = phase; onPhaseSync?.()`
**再** `await executePhase(...)`——**最后一次状态同步发生在提问之前**，
提问挂起后直到被答复前没有任何 `syncState()`。
视图 `availableActions` 的响应式依赖挂在 `void uiState.value`（Store 同步）上
→ 提问那一刻 Store 没变 → computed 不重算 →
**引擎等人、人等按钮，两边互等，第一回合死锁**。

### 正解：控制器自己报变更（`revision`）

控制器给 UI 的那几个答案（`pendingCardPlay` / `pendingDiscard` / 可打列表 / 技能面板）
**全是普通字段**，Vue 看不见；唯一能推出去的路（Store 同步）盖不住提问时刻。
→ `GameController` 新增 `revisionRef = ref(0)` + getter `revision`，
在**提问挂起 / 答复 / 状态同步**三处 `markChanged()`；
UI 三份 computed（`views/game/index.vue` 的 `availableActions` 与 `humanPlayer`、
`useCardPlay.playableCards`、`useSkill.availableSkills`）依赖一律改挂 `ctrl.revision`。
**没有**让引擎在提问时多推一次状态——那是往引擎里塞 UI 的心思。

### 第二处冻住（同一根因）：`humanPlayer` 早退陷阱

`humanPlayer` 在引擎出生前（`getGameState()` 为 null）就 `if (!state) return null` 早退，
**那一次根本没读到 Store**，注册的依赖只有 `session`（shallowRef）。
开局后 `session.value` 是同一个对象再没变过 → computed 永不重算 → 恒为 null
→ `<CardHand v-if="humanPlayer">` 一假到底，**手牌区整块空白**（按钮修好也点不到牌）。
修法：依赖**进门就挂**（`void ctrl?.revision`），不许放在早退之后。

### 两条测试纪律（本次新立）

- **端到端断言 UI 必须用 `watchEffect` 模拟渲染 effect**。
  直接读一次 `ctrl.getAvailableActions()` 永远拿得到新值（computed 一读就重算），
  掩盖 bug；只有把值写进一个 `ref` 挂到 effect 上，才测得到「依赖变了没有、界面重算过没有」。
- **「回合交出去了」不能只断言 `currentPlayerIndex !== HUMAN_SEAT`**：
  AI 那几位跑得快会绕回来又轮到人，那样断言照样绿。
  改成记录界面上**出现过的所有当前玩家**（`seenSeats`）+ 牌堆张数减少，双证据。

### 变异检验的坑（差点误判断言没牙齿）

`askCardPlay` / `askDiscard` 进门第一句就是 `settleAllPending()`，
而 `settleAllPending` 末尾也有 `markChanged()` → **单独**注掉 ask 里那句并不红，被补偿。
逐个单点变异 7 处**全绿**。改**组合**变异才现形：去掉 ask 路径三处 → 红 3 条，
再加 `syncToStore` → 红 4 条。hook 侧各去掉 → 各红 1 条；
视图 `humanPlayer` / `availableActions` 的依赖行各去掉 → 分别红 3 条 / 2 条。
